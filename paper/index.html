Content Decline Prioritisation Using Search Performance and Content Signals

Evaluating whether observable content and search-performance signals can help prioritise pages for human review.

FlyRank ML Internship · 2026

Abstract

This study asks whether observable content and search-performance signals can help identify pages that are more likely to be declining and therefore worth human review. Using an anonymized FlyRank ML Internship dataset, we evaluated Logistic Regression, Decision Tree, and Random Forest models using content age, update recency, impressions, average search position, CTR, and word count. Models were evaluated against a Week-4 rule-based baseline using the same client-holdout test set and Precision@50 as the primary ranking metric. Random Forest was the strongest of the tested machine-learning models with a Precision@50 of 0.54, but the simpler Week-4 baseline performed better at 0.58. These results support using model output as directional decision-support for prioritising human review, rather than as proof of future decline or evidence that refreshing content will cause improved performance.

1. Introduction / Problem Statement

Content teams often need to decide which pages should be reviewed first when search performance changes. A practical prioritisation system should identify useful signals without assuming that observed correlations prove causation.

This study evaluates whether observable content and search-performance signals can help rank pages that are more likely to be declining. The intended decision is therefore which pages should receive human review first, rather than whether a page should automatically be refreshed.

Research question: Can observable content and search-performance signals identify pages that are more likely to be declining and therefore worth review?

2. Data

Dataset

The analysis uses the anonymized FlyRank ML Internship content-refresh dataset.

  • Rows: 30,000
  • Columns: 44
  • Search-performance window: 90 days
  • Trend definition: comparison of the most recent 30 days with the preceding 30 days

Model Features

  • Content age
  • Days since last update
  • 90-day impressions
  • Average search position
  • Click-through rate (CTR)
  • Word count

Target

The target label is derived from trend_direction: pages with a value of down are labelled as declining.

Excluded Fields

  • trend_direction — defines the target
  • trend_pct — directly encodes the outcome
  • content_id — identifier only
  • client_id — used only for grouped validation

No client names, private queries, URLs, or other identifying information are included.

3. Methodology

Models

Three supervised classification approaches were evaluated:

  • Logistic Regression — interpretable linear reference model.
  • Decision Tree — simple rule-based model.
  • Random Forest — captures non-linear relationships and feature interactions.

Baseline

The Week-4 rule-based baseline flags a page when:

impressions_90d ≥ 500 AND avg_position > 0 AND ctr < 0.5

Validation

The preferred evaluation uses a client-holdout split. Twenty percent of clients are held out for testing so that pages from the same client do not appear in both training and test data.

The baseline and all models are evaluated on the same held-out rows. Precision@50 is used as the primary ranking metric because the practical goal is to create a small review queue.

Leakage Audit

Target-derived fields and identifiers were excluded from predictive features. The validation split was also checked for client overlap.

5. Limitations & Honest Framing

  • The dataset is an anonymized 30,000-row internship dataset and does not represent the full FlyRank research dataset.
  • The decline label describes observed trend_direction; it does not prove future decline.
  • The feature set does not capture seasonality, search-intent changes, technical SEO issues, competition changes, or external events.
  • Client-holdout validation is more conservative than a simple random row split, but the reported result is still based on one held-out split.
  • Random Forest did not outperform the simpler Week-4 baseline.
  • A model score does not establish that refreshing a page will cause improved performance.

The model should therefore be interpreted as a directional decision-support tool, not as an autonomous content-management system.

6. Ranked Recommendations

Model output should be used to prioritise pages for human review. Recommended actions depend on the observable reason signals and additional contextual review.

Signal Recommended Action
Low CTR + stale content Review CTR, search intent, content freshness, title and snippet alignment.
Low CTR Review title, snippet alignment and search intent.
Stale content Review whether information is outdated and whether a refresh is justified.
No strong signal Continue monitoring before taking action.

Human Review Required

Before taking action, reviewers should consider search intent, information freshness, technical factors, seasonality, competition, and business context.

Actions That Should Not Be Automated

  • Publishing or deleting content
  • Canonical, redirect, or indexing changes
  • Medical, legal, financial, or brand-safety decisions
  • Bulk rewriting solely because of a model score
  • Treating a refresh recommendation as proof of causal improvement
